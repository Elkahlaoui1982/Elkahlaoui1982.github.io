Method & focus

Research

My work is centered on security boundaries that look correct in the UI but break under role transitions, alternate endpoints, integrations, asynchronous flows, or stale authorization state.

01 · Authorization
Role boundaries, ABAC/RBAC enforcement, delegated permissions, stale privilege, cross-tenant isolation and alternate execution paths.
02 · Application logic
Business-logic assumptions, multi-step workflows, object ownership, state transitions and controls enforced in one path but missed in another.
03 · Integrations
Plugins, connectors, Jira-style integrations, AI agents and third-party execution paths where authorization context can be lost or reinterpreted.
04 · APIs & platforms
REST/GraphQL APIs, multi-tenant SaaS, cloud services, file/data boundaries, server-side processing and security-sensitive platform behavior.
Workflow

From source to reproducible evidence

DISCOVER

Map the boundary

Read source, routes, permission checks, schemas and role transitions. Look for duplicated functionality where one execution path may apply a different security decision.

VALIDATE

Separate attacker and victim state

Use controlled A/B accounts, independent browser profiles or isolated local/VPS labs to avoid session mixing and prove the authorization difference cleanly.

PROVE

Build end-to-end evidence

Confirm real impact with minimal canaries, clear before/after state and server-side persistence where relevant. Avoid relying on UI-only behavior.
